# 结合编排orchestrator和驾驭harness的skill设计

## 一、总则

通过 **orchestrator**（小模型）选取 *已有可关联的skill* 或 *可控探索技能* 规划可控工作流（大模型或者更合适的模型进行处理），高质量完成整个任务（任务边界限定）。

- **只以orchestrator为任务执行入口**
- 首先依托 意图分析算法 或 意图建模，分析用户意图 或 匹配历史任务相似度输出结果
- orchestrator使用小模型编排，节省Token
- 适时将任务拆分：子任务、subAgent 或 并行任务，缩短时间
- 任务使用合适的大模型执行，保证质量
- 任务完成度检测、完成质量检测，确保任务的完美
- 供编排skill选取，被编排skill选中的主skill完成任务后输出的结论，为编排任务下一个节点的输入提示词（或可匹配下一主skill的输入词）。
- 所有的任务节点

- 辅助harness必须可控，必须输出给用户确认
- 任务归档，方便总结常用的任务流程以生成预编排（提供预设的编排工作流）

## 二、概念

- 编排skill：全局编排器-只编排主skills，依据用户意图选取一个或多个主skill执行任务。需要执行多个skill时，对skill选择、调度编排、输出全局报告。决定做什么、用谁做、按什么顺序做、预算多少。

- 有向无环图DAG：编排skill依据用户意图生成的连接多个技能的依赖关系图

- 主skill：领域编排器-只编排自己的原子skill，主要做什么？选择原子skill、按照依赖关系决定原子skill的执行顺序（串行、并行）、整合业务结果。决定这件事怎么做才专业。

- 原子skill：主skill可拆分成的最小功能的实现单元，可分步骤串行执行、分模块并行执行。具体的操作实施。

- 预编排：提前预制一些主skill的组合流程供使用，也可在日常工作中总结出现频次多的流程自主生产编排流程。可直接使用的工作流。

## 三、约定

- 重试机制
- 消耗限额

## 四、工作流

只通过**orchestrator**作为入口，由 其（**任务复杂度判定算法**）判定任务复杂度：简单任务（1-3分）、中等任务（4-7）、复杂任务（8-10），依据不同难度执行不同的执行逻辑。

- 简单任务：
    智能体自主执行，不通过任何skill。

- 中等任务：
    通过orchestrator直接在skill注册表中选择 主skill，主skill选取相关的原子skill，按照前后依赖关系对原子skill进行编排生成流程图（按逻辑支持原子skill可并行执行，适时可以按照拆分子任务、subAgent进行执行）。

- 复杂任务：
    需要多个主skill生成工作流协同工作时。如依据需求文档-需求拆分-测试用例-代码编写-代码检测优化-测试优化-bug修复，整个流程可自主执行。此时需要每个主skill的输出，可触发下一个skill的执行。

**⚠️注意：** 当主skill缺失时，通过harness自主探索，生成明确可控执行流程给用户，确认后自主执行。
