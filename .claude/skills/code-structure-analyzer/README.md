# Code Structure Analyzer 使用说明

## 功能

读取项目中某个页面、业务模块或流程的代码，自动分析并生成结构化文档。

## 使用方式

```
/code-structure-analyzer <目标路径> [--depth <shallow|moderate|deep>]
```

### 示例

```bash
# 分析单个组件
/code-structure-analyzer src/views/UserList.vue

# 分析业务模块
/code-structure-analyzer src/store/modules/auth

# 深度分析（包含所有变量和依赖）
/code-structure-analyzer src/api/auth.ts --depth deep
```

## 输出

在目标文件/目录的同目录下生成 `{名称}.md` 文件：

- **代码概览**：文件数量、代码行数、技术栈
- **文件结构**：目录树
- **执行流程**：ASCII 流程图
- **关键节点**：入口点、分支点、循环点、API 调用点
- **重要变量**：状态变量、接口定义
- **依赖关系**：NPM 依赖、模块依赖、API 端点、环境变量
- **子元素引用**（可选）：本地组件/方法/工具函数的签名与逻辑摘要（由 D5 决策点控制）

## 韬定律增强

- **τ 控制**：根据分析深度自动分配预算
- **Task Folding**：代码扫描 + 依赖分析并行执行
- **Skill Stacking**：复用 scan-object-info 的技术栈上下文
- **Pattern Mining**：匹配已有模式，节省分析时间
- **D5 决策点**：自动检测本地子元素引用，按 τ 预算或用户选择决定是否展开读取其逻辑

## 深度选项

| 深度 | τ 预算 | 适用场景 |
|------|--------|---------|
| shallow | 3,000 | 快速了解结构 |
| moderate | 12,000 | 标准分析（默认），含子元素引用询问 |
| deep | 25,000 | 详细分析所有细节，含子元素完整逻辑 |

> τ 充足时（剩余 > 40%）自动展开子元素逻辑，不足时 prompt 用户选择

## 触发关键词

`分析代码结构`、`生成流程图`、`提取依赖关系`、`关键节点识别`、`变量提取`
