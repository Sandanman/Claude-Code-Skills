# Test Generator

## 概述

Test Generator 是前端项目的自动化测试生成技能，通过4个原子技能协同工作，从测试用例设计、框架检测、测试代码生成到验证确认，完整覆盖测试生成流程。支持 Vue/React 组件测试、API 集成测试、E2E 交互测试，适配 Vitest、Jest、Playwright、Cypress 等主流框架。

## 核心能力

- 分析源码和需求文档，设计覆盖正常路径、边界条件、异常场景的测试用例
- 自动检测项目已使用的测试框架和测试工具
- 生成符合项目规范的测试代码（单元测试/集成测试/E2E测试）
- 验证测试代码语法正确且可执行（无运行时错误）
- 支持测试覆盖分析，识别未覆盖的代码分支

## 执行流程

1. **test-case-design** - 设计测试用例，覆盖正常路径、边界条件、异常场景
2. **test-framework-detection** - 检测项目使用的测试框架（Vitest、Jest、Playwright）
3. **test-code-generation** - 根据测试用例设计生成测试代码
4. **test-verification** - 验证测试代码的正确性，确保测试可运行

## 原子skill依赖关系

- **test-case-design**: 无依赖
- **test-framework-detection**: 无依赖
- **test-code-generation**: 依赖 test-case-design, test-framework-detection
- **test-verification**: 依赖 test-code-generation

## 输入契约

- `target_path`：待生成测试的代码、模块或项目路径。
- `requirement_source`：可选的需求文档、接口描述或用户明确的测试目标。
- `test_types`：测试类型，可为 `unit`、`integration`、`e2e` 或组合值。
- `test_framework`：用户指定的测试框架；未指定时先检测，不得擅自选择默认框架。
- `output_path`：测试文件输出目录，由项目结构或用户指定。
- `run_tests`：是否执行生成后的测试，必须由用户或上层任务明确指定。
- `coverage_target`：可选覆盖率目标，未提供时不推断目标值。

## 输出契约

- 测试代码：写入指定目录，保持与检测到或用户指定的框架一致。
- 测试设计：记录正常路径、边界条件、异常场景及其覆盖关系。
- 验证结果：分别记录静态检查、类型或语法检查、测试收集/编译检查和实际执行结果。
- 未覆盖场景：明确列出原因和后续建议。
- 返回状态：`passed`、`partial`、`failed` 或 `cancelled`。

## 主 Skill 完成标准

1. 目标代码、需求文档或测试目标已成功读取并完成范围确认。
2. 测试用例覆盖正常路径、边界条件和异常场景；无法覆盖的场景已记录原因。
3. 测试框架已通过用户指定或项目证据检测确认，未使用未经确认的默认框架。
4. 测试代码与框架语法、项目语言和现有配置一致。
5. 已执行的静态检查、类型/语法检查、测试收集或实际测试结果均已记录。
6. 生成的测试文件已保存到正确目录，且未覆盖已有测试文件。

## 完成后校验

在报告任务完成前必须逐项检查：

1. 测试目标与用户指定的代码、需求和测试类型一致。
2. 测试框架来源可追溯；检测失败且未获用户确认时不得生成框架特定代码。
3. 每个核心场景都有对应测试，或已记录未覆盖原因。
4. 测试文件存在、非空、可读取，路径符合项目结构或用户指定路径。
5. 测试代码已完成可执行的静态、类型/语法或测试收集检查，并记录实际结果。
6. 未经用户要求不得执行完整测试套件；未执行实际测试时必须明确标记。
7. 生成结果不覆盖已有测试文件，测试设计、代码和验证结果相互一致。
8. 任一核心校验失败时不得报告 `passed`，应返回 `partial` 或 `failed`。

## 状态与错误处理

- `passed`：测试设计、代码生成、指定验证和完成后校验全部成功。
- `partial`：框架信息缺失、部分场景无法覆盖、未执行实际测试或存在非阻塞验证问题，但产物可用。
- `failed`：目标读取、核心生成、文件写入或完成后校验失败。
- `cancelled`：用户取消生成或验证，不覆盖已有测试文件。

框架检测失败时暂停生成并等待用户指定框架；不得使用默认 Vitest 或其他未经确认的框架补全结果。

## 重试规则

- 每个原子skill失败后可重试 **3次**
- test-framework-detection 失败：暂停生成并等待用户指定测试框架；不得使用未经确认的默认框架。
- test-code-generation 失败：保留已确认的测试设计，修复原因后重试，不擅自减少核心场景覆盖范围。

## 注意事项

- 生成测试代码前先检查项目是否有 `vitest.config.ts` 或 `jest.config.js`
- E2E 测试需要项目有对应的页面路由
- 生成的测试代码需要人工review，不自动执行完整测试套件
- 边界条件和异常场景的测试用例设计需结合业务逻辑
