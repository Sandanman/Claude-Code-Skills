# Product Designer

> 将用户简单的需求描述扩展为完整的产品模块设计方案，替代产品经理工作。

## 触发方式

```bash
/product-designer
```

或通过 orchestrator-pro 自动调度。

## 核心原则

- **75/25 原则**：75% 深挖需求本身，25% 合理发散
- **零臆想原则**：不确定部分必须向用户提问，不私自假设
- **交互驱动**：关键决策点必须等待用户确认

## 输入示例

用户只需输入一两句话的需求描述，例如：
> "实现一个用户反馈提交功能"

## 输出产物

输出至 `.claude/skills/product-designer/outputs/{product_name}_{timestamp}/`：

| 文件 | 说明 |
|------|------|
| `01_产品模块设计文档.md` | 完整设计主文档 |
| `02_功能清单.md` | 功能点汇总表（含优先级） |
| `03_API接口规格.md` | 接口详细定义 |
| `04_验收条件.md` | Given-When-Then 验收条件 |

## τ 预算

| 档位 | τ 预算 | 说明 |
|------|--------|------|
| simple | 3,000 | 单角色、单功能模块 |
| moderate | 8,000 | 3-5角色、多功能模块 |
| complex | 15,000 | 多角色、多功能模块、含集成 |
