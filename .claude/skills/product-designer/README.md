# Product Designer

> 将用户简单的需求描述扩展为完整的产品模块设计方案，替代产品经理工作。

## 触发方式

```bash
/product-designer
```

或通过 orchestrator 自动调度。

## 核心原则

- **75/25 原则**：75% 深挖需求本身，25% 合理发散
- **零臆想原则**：不确定部分必须向用户提问，不私自假设
- **交互驱动**：关键决策点必须等待用户确认

## 输入示例

用户只需输入一两句话的需求描述，例如：
> "实现一个用户反馈提交功能"

## 输出产物

输出至 `.claude/skills/product-designer/outputs/{product_name}_{timestamp}/`：

| 文件 | 说明 |
| --- | --- |
| `01_产品模块设计文档.md` | 完整设计主文档 |
| `02_功能清单.md` | 功能点汇总表（含优先级） |
| `03_API接口规格.md` | 接口详细定义 |
| `04_验收条件.md` | Given-When-Then 验收条件 |
| `05_业务逻辑流程.md` | Mermaid 核心业务流程和异常流程 |

## 完成与校验

- 每个 P1 功能必须有完整的业务详细描述和至少 1 张 Mermaid 流程图。
- 每个 P1 功能必须包含至少 2 个 Given-When-Then 验收场景。
- 不确定内容标记 `[待确认]`，发散内容标记 `[建议]`，不得自行补全业务假设。
- 输出前校验 5 个文件均存在、非空、可读取，且跨文件的模块名称、版本、功能 ID、角色和优先级一致。
- 任一校验失败时返回失败原因，不报告任务完成。
