# Project Cloud Map

## 目标与边界

读取整个项目当前代码快照，生成可审阅的项目云图，说明项目类型、入口、页面/入口组织、模块协作、数据流、交互链路及关键文件/符号。只描述当前快照，不读取、调用或推断 Git 历史，包括 commit、branch、tag、blame、diff、提交时间和历史演进。

这是只读分析 Skill。默认不修改项目代码、配置和业务文档；未指定报告文件时直接输出 Markdown。遵循项目忽略规则排除依赖缓存、构建产物、二进制和明显密钥，并说明排除项。重要结论绑定实际文件路径，必要时标注函数、类、组件、路由名或配置键；无法确认时标注“未发现”或“推测”。

## 执行流程

1. 从项目根目录读取完整目录树、源码、配置、资源、测试和文档，识别 package.json、pyproject.toml、go.mod、Cargo.toml、pom.xml、Makefile、Dockerfile、环境变量模板、构建/运行脚本及所有入口。扫描路由、页面、组件、服务、控制器、模型、状态容器、API 客户端、命令注册和公共导出，记录扫描和排除范围。不得只抽样文件。
2. 根据证据自动判断一个或多个类型：Web、全栈、后端、CLI、库。Web 需有前端入口/路由/页面；全栈需同时有前端和后端边界；后端需有服务入口且无前端主要入口；CLI 需有命令解析或子命令注册；库需主要提供公共导出或 SDK/API。不要仅凭目录名判断。
3. Web/全栈按页面、路由、布局和用户流程拆分，再按数据流与交互逻辑细分模块；后端按服务入口、业务域、控制器/处理器、服务、数据访问和外部集成拆分；CLI 按命令、子命令、参数解析、执行器、输出和外部依赖拆分；库按公共导出、核心模块、适配器、模型和调用链拆分。
4. 对每个页面或入口追踪：触发者 → 入口文件/符号 → 状态或参数 → 服务/API/数据库/外部系统 → 返回数据 → 状态更新 → 渲染、终端输出或响应。记录事件、表单、导航、权限分支、异步边界、错误、加载、缓存、重试、共享状态和副作用。

## 输出格式

始终输出 Markdown + Mermaid，至少包含：项目类型与快照范围、入口总览、页面/入口清单、模块拆分与职责、页面或入口到模块的关系图、核心数据流图或表、交互链路与关键分支、文件/符号索引、未确认项与扫描限制。Mermaid 节点 ID 应稳定简短，只绘制有代码证据的关系，推测关系明确标注。

## 代码变更前确认

如果用户同时要求新增或修改代码，先完成云图，然后只列候选方案并等待确认，不得修改代码：

| 候选页面 | 候选模块 | 文件/符号 | 拟变更内容 | 预计时间范围 | 影响范围 |
|---|---|---|---|---|---|
| 页面或入口名 | 模块职责 |  或  | 具体新增/修改/删除 | 例如 30–60 分钟 | API、状态、测试、部署等 |

明确说明：“以上仅为候选变更，尚未修改代码。请确认要执行的范围；收到明确确认后才会改代码。”确认前不得使用会改变代码的工具。
