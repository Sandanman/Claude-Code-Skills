# Project Planner 主 Skill v1.0（项目进度规划与每日工作生成器）

> 本 Skill 基于用户提供的任务规划，在指定迭代周期内自动生成项目目标分解、每日工作内容及项目进度追踪，支持多项目分组管理和超期预警，具备历史速度学习能力动态调整估算精度。

## 版本历史

- **v1.0** (2026-06-18): 初始版本，支持动态估算调整、多项目分组、超期预警

---

## 核心设计理念

### 三大核心能力

| 能力 | 说明 |
| --- | --- |
| **目标驱动** | Goal/KR → 任务 → 每日工作，自顶向下拆解，每步可回溯 |
| **动态精算** | 基于历史速度（实际/预估偏差系数 EWMA）持续修正估算精度 |
| **透明预警** | 进度偏差量化分级（黄/橙/红），阻塞原因显式标注 |

### 估算精度原则

| 估算精度原则 | 规则 |
| --- | --- |
| **偏差系数** | 实际工时 / 预估工时（>1 表示原估算偏乐观，<1 表示原估算偏保守） |
| **历史聚合** | 按任务类型累计偏差系数，不同类型分别计算 |
| **平滑方式** | 采用 EWMA，近期数据权重更高 |
| **无历史数据** | 默认偏差系数为 1.0，不做调整，并标记为无历史参考 |
| **更新时机** | 任务完成后重算参考系数，并更新受影响的未完成任务预估 |

---

## 核心能力

- **迭代周期规划**：周/双周/月，支持自定义起止日期，自动排除周末和法定节假日
- **里程碑标记**：与项目截止日期对齐，关键节点可视化
- **目标 → 任务双向拆解**：自顶向下拆解 + 自底向上回填，未完成自动结转
- **每日工作内容生成**：按项目分组，支持优先级浮动排序
- **项目进度追踪**：独立进度条 + 全局汇总，健康度打分
- **超期分级预警**：黄（≤20%）/ 橙（≤50%）/ 红（>50%）
- **跨项目资源冲突检测**：同一时间段多个高优先任务撞车预警
- **历史速度学习**：动态偏差系数 + EWMA + 可信度分级（⚠️ 标记低可信度）
- **多种输出格式**：日报/周报/仪表盘，纯 Markdown，可一键复制

## 输入校验规则

- `iteration_type` 必须为 `weekly`、`biweekly`、`monthly` 或 `custom`。
- `custom` 必须提供合法日期，且 `iteration_start` 不晚于 `iteration_end`；其他类型由周期类型确定日期范围。
- `projects` 和 `tasks` 必须为数组；每个项目名称唯一，每个任务名称唯一且引用存在的项目。
- `estimated_hours` 必须大于 0；`daily_capacity` 必须大于 0；`allocation_ratio` 必须大于 0 且不大于 1。
- 所有日期字段必须为 `YYYY-MM-DD`；`depends_on` 只能引用已存在任务，依赖图不得形成环。
- `output_preference` 只能为 `daily`、`weekly`、`dashboard` 或 `all`。
- 输入不满足规则时停止排程，返回 `failed`，不得使用猜测值补全业务数据。

## 排程边界

- 所有可排程任务必须分配到工作日；受循环依赖、阻塞、容量不足或截止日期限制而无法排程的任务，必须记录原因、影响范围和建议动作。
- 循环依赖属于输入错误，停止排程并返回 `failed`。
- 容量不足或外部阻塞属于可部分完成情况，生成已有结果并返回 `partial`。

## 动态估算精度调整

### 4.1 历史速度学习

```text
每次任务完成 → 记录偏差系数 → EWMA 平滑 → 更新参考系数

偏差系数 = 实际工时 / 预估工时
  >1.0：原估算偏乐观，后续预估应增加
  <1.0：原估算偏保守，后续预估可减少
  ≈1.0：估算体系可信

按任务类型分组累计（dev/test/design/review/deploy/other）
EWMA 权重：近期任务权重更高（衰减因子 α = 0.7）
```

### 4.2 估算修正公式

```
调整后预估 = 原始预估 × EWMA_偏差系数

EWMA_偏差系数计算：
  EWMA_t = α × ratio_t + (1-α) × EWMA_{t-1}
  其中 α = 0.7（近期权重），EWMA_0 = 1.0（无历史时默认值）
```

### 4.3 可信度分级

| 等级 | 历史样本数 | 标记 | 说明 |
|------|-----------|------|------|
| 高 | ≥5 | 无 | 估算可信 |
| 中 | 3~4 | 无 | 基本可信 |
| 低 | 1~2 | ⚠️ | 建议复核 |
| 无数据 | 0 | ⚠️⚠️ | 无历史参考，需人工确认 |

## 进度追踪与预警

### 预警偏差定义

`偏差`在超期预警中专指计划工时与实际工时的相对差异：

```text
偏差 = (实际工时 - 预估工时) / 预估工时 × 100%
```

日期延期和进度落后分别记录，不与工时偏差混用。

| 等级 | 条件 | 标记 | 建议动作 |
| --- | --- | --- | --- |
| 正常 | 偏差 ≤20% | ✅ | 正常执行 |
| 黄牌 | 20% < 偏差 ≤50% | 🟡 | 关注，评估是否需要资源调整 |
| 橙牌 | 50% < 偏差 ≤100% | 🟠 | 预警，需要采取纠正措施 |
| 红牌 | 偏差 >100% | 🔴 | 严重超期，考虑重新评估计划 |

### 项目健康度打分

```text
健康度 = 0.4 × 进度分 + 0.3 × 风险分 + 0.3 × 阻塞分

进度分 = 总任务数为 0 时记为 null，否则为已完成任务数 / 总任务数（0~1）
风险分 = 总任务数为 0 时记为 null，否则为 1 - 超期任务数 / 总任务数（0~1）
阻塞分 = 未完成任务数为 0 时记为 1.0，否则为 1 - 阻塞任务数 / 未完成任务数（0~1）

健康度只对可计算的分项加权归一化；没有可计算分项时记为“无数据”，不得生成虚假分数。
健康度 ≥ 0.8：优秀 🟢
健康度 0.6~0.8：良好 🟡
健康度 < 0.6：需关注 🔴
```

### 跨项目冲突检测

```text
同一工作日，同一优先级（≤2）任务数 > 每日容量时：
  → 标注 [⚠️ 资源冲突：项目A(3h) + 项目B(4h) > 每日容量(6h)]
  → 建议调整优先级或延长迭代周期
```

## 主 Skill 完成标准（v1.0，8项）

1. **输入校验通过**：周期、日期、项目、任务、依赖和输出偏好符合输入规则。
2. **迭代周期正确**：工作日计算无误，排除周末和已知节假日。
3. **任务排程完整**：所有可排程任务均已分配；无法分配的任务记录原因、影响范围和建议动作。
4. **里程碑对齐**：项目截止日期正确关联里程碑。
5. **偏差系数已计算**：EWMA 偏差系数正确，含可信度标注；无历史数据时明确标记无历史参考。
6. **超期预警已生成**：黄、橙、红分级准确，且工时偏差、日期延期和进度落后不混用。
7. **请求的输出已生成**：按 `output_preference` 写入对应文件和规划存档。
8. **任务状态已更新**：成功执行时 `task_skill.md` 状态正确。

## 完成后校验

在报告任务完成前必须逐项检查：

1. 校验输出目录存在，所有应生成文件均存在且非空。
2. 校验输出文件集合与 `output_preference` 一致；共享任务状态文件始终单独校验。
3. 校验项目、任务、依赖、里程碑和排程结果与输入一致。
4. 校验未排程任务均记录原因、影响范围和建议动作。
5. 校验偏差系数、EWMA、可信度、健康度和预警等级可计算且边界处理正确。
6. 校验 Markdown 文件可读取，表格和代码块结构完整。
7. 校验 `task_skill.md` 已写入当前任务状态、执行结果和问题记录。
8. 增量更新时校验受影响任务及其依赖链已重算，未受影响的历史结果未被改写。
9. 任一校验失败时不得报告 `passed`；根据影响返回 `partial` 或 `failed`。

---

## 状态与错误处理

- `passed`：输入、排程、请求的输出、共享状态和完成后校验全部成功。
- `partial`：存在容量不足、外部阻塞或无法排程任务，但可用结果已生成并明确列出问题。
- `failed`：输入校验、循环依赖、核心计算、文件写入或完成后校验失败。
- `cancelled`：用户取消生成或更新，不覆盖已有输出。

输入无效、循环依赖或核心文件写入失败时停止后续生成，不使用猜测值补全业务数据。

---

## 增量更新规则

- 修改任务时，重算该任务、直接或间接依赖它的任务，以及受影响项目的汇总和报告。
- 任务完成状态变化时，重新计算相关任务类型的偏差系数和 EWMA。
- 未受影响的任务、历史记录和历史归档内容保持不变。
- 已存在的日报、周报和仪表盘按同一输出路径更新；规划存档追加本次变更记录，不删除历史记录。
- 删除任务前校验依赖引用；仍被其他任务依赖时返回 `failed`。

## 节假日处理

- 默认节假日数据必须覆盖当前迭代年份，并明确数据来源或标记为待确认。
- `holidays` 作为额外排除日期追加到默认节假日列表，不覆盖默认数据。
- 调休工作日必须通过有效工作日列表显式传入；仅提供节假日列表时，不推断调休安排。
- 节假日数据缺失或年份不覆盖迭代周期时返回 `partial`，并在报告中标记人工确认项。
