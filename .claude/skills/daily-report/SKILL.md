# Daily Report 主 Skill（桌面月度日报 / 周报 / 月报生成器）

> 把某一天的实际工作整理成纯文本日报，按月写入 `~/Desktop/日报/YYYY年MM月.txt`；日报按周分组，每周附周报，月末附月报。默认今日，可指定日期；同日重复执行只追加不重复的内容；多个终端可同时读取和写入。

## 版本历史

- **v1.2** (2026-11-19): 月文件改为“标题头 + 周分组 + 周报 + 月报”结构；日期标题带星期；新增周报、月报并支持单独生成/刷新；兼容并自动迁移 v1.1 旧格式。
- **v1.1** (2026-11-18): 新增“其他终端会话”内容来源；锁释放改为显式 `rmdir`，`trap` 仅作兜底。

## 触发与边界

| 场景 | 处理 |
| --- | --- |
| “输出今日日报”“生成日报”“工作总结” | 本 Skill，日期为今天 |
| “输出 11 月 15 日日报”“补写昨天的日报” | 本 Skill，日期为指定日期 |
| “生成本周周报”“输出桌面周报”“刷新第 3 周周报” | 本 Skill，`scope=week` |
| “生成本月月报”“输出 10 月月报” | 本 Skill，`scope=month` |
| “迭代计划”“每日计划”“进度追踪”“超期预警”，以及 `project-planner` 的周目标完成率类周报 | 不属于本 Skill，走 `project-planner` |

本 Skill 的周报、月报是对桌面日报文件内容的归纳，只总结“已经做了什么”，不做排程、估算、进度和预警。`project-planner` 的当日排程文件可作为可选参考来源，但不是依赖。

## 输入

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `scope` | 否 | `day`（默认）：整理日报并联动刷新周报、月报；`week`：只依据已有日报生成/刷新 `date` 所在周的周报并联动月报；`month`：只刷新 `date` 所在月的月报 |
| `date` | 否 | 目标日期，默认今天。接受 `YYYYMMDD`、`YYYY-MM-DD`、`MM月DD日`（年份取今年）、`今天`/`昨天`/`前天`。仅支持单个日期；多天请分次执行。`scope=week/month` 时用于定位目标周/月 |
| `items` | 否 | 用户直接给出的条目（项目名 + 内容）。给出时优先使用 |
| `project` | 否 | 条目所属项目名；未给出时按“项目归属”规则判定 |

### 日期校验

- 日期必须是真实存在的日历日期；无法解析时返回 `failed` 并询问，不猜测。
- 晚于今天的日期拒绝写入，返回 `failed`（不为未来写日报）。
- 目标月份文件由**目标日期**决定，与执行当天无关；跨月补写只改动对应月份文件。

## 内容来源

按下表确定条目，优先级从上到下，**不得臆造没有依据的工作内容**：

| 优先级 | 来源 | 适用 |
| --- | --- | --- |
| 1 | 用户在请求中直接给出的条目 | 任意日期 |
| 2 | 当前会话中已完成的实际工作 | 仅目标日期为今天 |
| 3 | 当前仓库该日期的提交：`git log --author="$(git config user.name)" --since="D 00:00" --until="D 23:59:59"` | 任意日期 |
| 4 | `docs/lijianxin/tasks/history/YYYY-MM/` 中该日期归档的任务摘要 | 任意日期 |
| 5 | 本机其他终端（其他 Claude Code 会话）当天的工作，见下方“其他终端会话” | 任意日期（会话记录仍保留时） |

- 同时有多个来源时合并后统一去重。
- 来源 3 的提交范围扩展到来源 5 中各会话工作目录所在的 git 仓库（按仓库去重，逐个仓库执行同样的 `git log`）。
- 所有来源都没有可用内容时，不写文件，向用户索取该日工作内容，状态为 `partial`。
- 提交信息、任务摘要需要改写成“做了什么”的一句话，不照搬 hash 或任务 ID。
- 输出摘要中必须列出本次条目及来源，便于用户核对。

### 其他终端会话（来源 5）

目的：日报要覆盖“今天所有终端做了什么”，而不只是当前终端。

1. **发现**：查找 `~/.claude/projects/*/*.jsonl` 中修改时间不早于目标日期 00:00（本地时区）的会话文件，不设上限（补写历史日期时，当天开始、之后才收尾的会话 mtime 更晚）。当前会话已由来源 2 覆盖；无法区分当前会话时不排除，交给去重处理。
2. **提取**：只读其中 `type=user` 的纯文本请求，跳过以 `<` 开头的系统注入内容和 Skill 展开文本。记录里的 `timestamp` 为 UTC，必须换算成本地时区后再按目标日期过滤，跨午夜的请求按本地日期归属。
3. **取证**：请求只是线索，不是结论。每条必须有至少一项可核实证据才能写入：
   - 该会话工作目录（`cwd`）所在仓库当天由当前用户提交的 commit；
   - 当天生成或修改的产出文件（如桌面文档）；
   - 其他可直接核对的结果。
4. **状态类表述必须核实**：写“已推送”“已合并”“已发布”等状态前，用 `git status -sb`、`git ls-remote` 等核对；无法核实或核实结果相反时，写“本地合并（尚未推送）”之类的实际状态，或省略该状态。
5. **无证据的请求不写入**：只有请求、没有任何证据的内容（含只是提问、方案讨论、被中断的请求）不写入日报，在输出摘要中列为“未采纳”，让用户决定是否补充。
6. **归属**：按“分组规则”判定，项目名取该会话 `cwd` 所在 git 仓库名；非项目内容取做这件事时的工作目录名，并在输出摘要中说明，方便用户改名。
7. **隐私**：只读取本机当前用户自己的会话记录；日报条目只写一句话概括，不照搬请求原文、接口返回、token、密钥或长 JSON。

参考命令（macOS）：

```bash
# 目标日期 D（YYYY-MM-DD）之后有更新的会话文件（只设下限）
find ~/.claude/projects -maxdepth 2 -name '*.jsonl' -newermt "$D 00:00:00"
# 再按记录内 timestamp（UTC→本地）筛出落在 D 当天的用户请求
```

## 日报格式

纯文本，按月一个文件（路径见“文件系统位置”）。整体结构依次为：**标题头 → 若干周块（每周：周分隔块 + 按日期升序的日报段落 + 周报）→ 月报**。

```text
=====================
｜YYYY年MM月 日报  ｜
=====================

——————-
｜MM月第1周｜
——————-

YYYYMMDD 周*

1、A项目 某模块
2、A项目 ***
3、B项目 ***

YYYYMMDD 周*

1、...

MM月第1周 周报
———————
【A项目】
本周A项目的工作概述（20～60字）

【B项目】
本周B项目的工作概述（20～60字）

——————-
｜MM月第2周｜
——————-

YYYYMMDD 周*

1、...

MM月第2周 周报
———————
【A项目】
本周A项目的工作概述（20～60字）

YYYY年MM月 月报
===============
【A项目】
本月A项目的工作概述（20～80字）

【B项目】
本月B项目的工作概述（20～80字）
```

结构约定：

- **标题头**：文件前三行为 `=` 线、`｜YYYY年MM月 日报  ｜`（竖线为全角 `｜`，月份后一个空格，结尾竖线前两个空格）、`=` 线，其后空一行。
- **周分隔块**：每周开头三行为 `—` 线、`｜MM月第N周｜`、`—` 线，其后空一行再写该周第一个日期段落。
- **日期标题**：`YYYYMMDD 周*`，`*` 取 `一 二 三 四 五 六 日`，如 `20261118 周三`；日期标题与第一条之间空一行，日期段落之间空一行。条目格式见“日期段落”。
- **周报**：位于该周最后一个日期段落之后，空一行起，格式为 `MM月第N周 周报`、`—` 线、按分组键拆分的周报正文（见下文“周报”）；与下一周分隔块之间空一行。
- **月报**：位于文件末尾，空一行起，格式为 `YYYY年MM月 月报`、`=` 线、按分组键拆分的月报正文（见下文“月报”）。
- 周报、月报为派生内容：只出现“有日报”的周/月；无日报的周不生成周块，无任何周报的月份不生成月报。

### 分隔线长度

每条分隔线的**显示宽度与其所修饰的标题行相同**：全角字符（含 `｜`、汉字）宽度按 2，半角字符（数字、字母、空格、`.`、`-`）按 1。

- `=` 线：用半角 `=`，个数等于标题行显示宽度。
- `—` 线：用全角破折号 `—`（每个宽度 2），个数为标题行显示宽度的一半（向下取整）；宽度为奇数时末尾补一个半角 `-`。
- 适用于：标题头上下两条、周分隔块上下两条、周报标题下方一条、月报标题下方一条。
- 例：`｜2026年11月 日报  ｜` 宽度 21 → 21 个 `=`；`｜11月第4周｜` 宽度 13 → 6 个 `—` + `-`；`2026年11月 月报` 宽度 15 → 15 个 `=`。
- 计算方式：按 Unicode East Asian Width，`W`/`F` 记 2，其余记 1（如 Python `unicodedata.east_asian_width`）。

### 周的划分

- 每周从**周一**到**周日**；`N` 为该日期在本月内所属的周序号：**该月 1 日所在的周为第 1 周**，此后每个周一进入下一周。
- 计算：`N = (日 - 1 + 该月1日的周几偏移) // 7 + 1`，其中周一偏移为 0、周日偏移为 6。例：11 月 1 日是周日（偏移 6），11/1 为第 1 周，11/2（周一）为第 2 周。
- 跨月的周按自然月拆开：各月文件各自把本月内的日期归入本月的周块，周报只总结本月内的日期。

### 日期段落

当日只有一个分组时为平铺格式（条目直接列在日期标题下，见“日报格式”示例）；出现多个分组时：

```text
20261118 周三

【A项目】
1、A项目 某模块
2、A项目 ***

【B项目】
1、B项目 ***

【web-admin】
1、排查本地构建报错
```

格式约定：

- 条目固定为 `{序号}、{项目名} {工作内容}`，一行一条，不使用 Markdown 语法；非项目条目省略项目名，写成 `{序号}、{工作内容}`。
- 当日只有一个分组时省略 `【xxx】` 标题；出现第二个分组时，把已有条目补上原分组标题后再追加新分组。
- 日报只记录工作内容，不含偏差、预警和明日计划。

### 周报

- **来源**：仅依据该周已写入文件的每日日报内容，不另行收集新内容，不引入日报中没有的事项。
- **分项目/终端**：按分组键拆成多段，每个分组一段，格式为 `【分组键】` 一行 + 概述一行，段与段之间空一行；分组键与日报一致（项目优先，非项目内容取终端工作目录名），顺序按该分组在本周首次出现的先后。同一分组的多天工作合并为一句概括，不照搬日报全文、不逐条罗列、不带序号。
- **篇幅**：**每个分组的概述为 20～60 字**（含标点，不含 `【分组键】` 标题行）；超出时合并同类、舍去次要事项，不足时补充该分组本周的关键成果，不得靠截断凑数造成语句不完整。
- **平铺旧段落**：日期段落只有一个分组且无 `【xxx】` 标题时，该日条目按其项目名归组；条目无项目名时归入该日写入终端的工作目录名，无法判断时在输出摘要中说明归属并请用户确认。

### 月报

- **来源**：仅依据本月各周的周报正文，不回读日报明细，不引入周报中没有的事项。
- **分项目/终端**：与周报相同，按分组键拆成多段；本月任一周出现过的分组都要有一段，同一分组跨周的工作合并概括。
- **篇幅**：**每个分组的概述为 20～80 字**（含标点，不含标题行）。

### 分组规则（优先级从高到低）

1. **项目优先**：条目属于某个项目时，分组键为项目名；不同终端写入的同一项目条目合并到同一个 `【项目名】` 组。
2. **非项目内容**：与任何项目无关的杂项，分组键为做这件事时所在终端的工作目录名（`basename "$PWD"`；其他终端会话取其 `cwd` 的目录名）。
3. 项目名与目录名相同视为同一分组。

项目归属判定：用户指定的项目名 > 条目内容中明确出现的项目名 > 当前工作目录所在 git 仓库名（开发类工作；其他终端会话取其 `cwd` 所在仓库名）。仍无法判断时按非项目内容处理。

## 写入规则

**写入范围总则**：只改目标日期段落内的目标分组，以及目标周的周报和月报；不改动其他日期、其他分组、其他周的周报和其他终端已写入的条目。无新增条目时不改动文件（含不迁移格式）。

### 1. 路径与创建

- 输出目录不存在时创建；月度文件不存在时创建并写入标题头（见“日报格式”）。
- 目标日期的周块不存在时，**按周序号升序插入**；目标日期段落不存在时，**按日期升序插入到所属周块内的正确位置**（补写历史日期时插在对应日期之间，不追加到文件末尾）。
- **旧格式迁移**：读取到 v1.1 旧格式（首行为 `YYYY年MM月日报`、日期标题无星期、无周块）时，写入前先在内存中转换为新格式：替换标题头、给日期标题补星期、按“周的划分”归入周块，已有条目原样保留；再按下文规则生成周报、月报。迁移与本次写入在同一次加锁写入中完成。无新增条目时不迁移，文件保持原样，待下次有新增或 `scope=week/month` 时一并迁移。

### 2. 追加去重

- 目标日期段落已存在时，只在该段落内追加本次新增条目。
- 去重键为“项目名 + 工作内容”，比较前去除序号前缀、首尾及连续空白和中英文标点；当日所有分组共用同一去重范围。周报、月报不参与去重。
- 重复条目直接跳过；全部重复时不修改文件，报告“无新增”。
- 新增条目追加到对应分组末尾并沿用该组连续序号，不重排已有序号。

### 3. 周报与月报的生成与刷新

- **触发**：`scope=day` 时，仅当本次有新增条目，才重写目标日期所在周的周报并联动重写月报（避免覆盖用户手工调整过的总结）；`scope=week` 强制重写目标周周报并联动月报；`scope=month` 只重写月报。
- **时机**：周报、月报与日报同一次加锁写入，在去重合并后、原子写入前生成，保证文件内容自洽。
- **字数校验**：生成后逐分组统计字数，不符合“周报”“月报”两节要求时重写。
- **分隔线**：重写周报、月报或迁移旧格式时，按“分隔线长度”重新计算各线长度。
- **位置**：周报紧随该周最后一个日期段落；月报始终位于文件末尾（月内有日报时必有对应周报，月报才存在）。

### 4. 多终端并发读写

多个终端（Claude Code 会话）共享同一个月度文件。

- **读取**：任一终端可读取指定日期的全部分组；只读不加锁。
- **加锁写入**：用 `mkdir` 创建锁目录（路径见“文件系统位置”）作原子锁，失败每 0.5 秒重试，最多 10 秒；锁目录存在超过 60 秒视为残留锁，清理后重试；仍拿不到锁则返回 `partial`，不强写。
- **加锁后必须重新读取文件**，基于最新内容去重并生成新内容，写入同目录临时文件后 `mv` 原子替换，最后**显式 `rmdir` 释放锁目录**，`trap` 仅作异常退出时的兜底（部分执行环境中 `trap EXIT` 不会在命令结束时立即触发，不能只依赖它）。

参考实现（bash，macOS）：

```bash
DIR="$HOME/Desktop/日报"; LOCK="$DIR/.lock"
mkdir -p "$DIR"
n=0
until mkdir "$LOCK" 2>/dev/null; do
  age=$(( $(date +%s) - $(stat -f %m "$LOCK" 2>/dev/null || date +%s) ))
  [ "$age" -gt 60 ] && rmdir "$LOCK" 2>/dev/null
  n=$((n+1)); [ "$n" -ge 20 ] && { echo "获取锁失败"; exit 1; }
  sleep 0.5
done
trap 'rmdir "$LOCK" 2>/dev/null' EXIT   # 兜底
# 加锁后：重新读取月度文件 → 去重 → 写临时文件 → mv 原子替换
rmdir "$LOCK"; trap - EXIT                  # 显式释放
```

## 执行流程

```text
1. 解析日期与范围  → 默认今天、scope=day；校验日期合法且不晚于今天
2. 收集内容        → scope=day：按“内容来源”优先级取条目（含其他终端会话取证），无依据则询问；scope=week/month：跳过，直接读取已有日报
3. 归属与分组      → 判定项目名 / 工作目录分组键（scope=day）
4. 加锁并读取      → 获取锁，读取目标月份文件（不存在则准备新建；旧格式则内存迁移）
5. 去重与合并      → 定位或插入周块与日期段落，追加不重复条目，必要时补分组标题
6. 生成周报月报    → 有新增条目（或 scope=week/month）时，重写目标周周报并联动月报（字数与分隔线按各节规则）
7. 原子写入        → 临时文件 → mv → 释放锁
8. 校验与输出      → 读回校验并输出本次新增、跳过、未采纳及来源，附周报、月报正文与字数
```

路由：默认 `fast`（L0 校验）；内容来源不足需向用户确认、其他终端会话证据相互矛盾、拿不到锁需重试或恢复时升级为 `durable`。`scope=week/month` 目标周/月没有日报时返回 `partial` 并说明，不生成空周报/月报。

---

## 状态

- `passed`：日期合法，条目已写入或确认无新增，周报月报已按规则刷新或确认无需刷新，读回校验通过，锁已释放。
- `partial`：无可用内容待用户补充，或拿不到锁未写入，或 `scope=week/month` 的目标周/月无日报。
- `failed`：日期无法解析或晚于今天，写入失败或读回校验失败。
- `cancelled`：用户取消，不改动文件。

---

## 完成标准

1. 目标日期合法，月份文件路径由目标日期决定。
2. 结构符合“日报格式”：标题头与周分隔块正确，日期标题为 `YYYYMMDD 周*` 且星期与日期一致，周内升序不重复，所属周与“周的划分”一致。
3. 条目均有依据并已列出来源；其他终端会话已扫描，来自其的条目均有可核实证据，状态类表述已核实，无证据的请求已列为“未采纳”。
4. 同日条目无重复；分组符合“分组规则”（仅一个分组时为平铺格式）；未改动写入范围之外的内容。
5. 每个有日报的周紧随其后有周报，月报位于文件末尾；分组齐全，字数与来源符合“周报”“月报”两节，各分隔线宽度符合“分隔线长度”。
6. 写入经加锁、重读、临时文件原子替换，锁目录已显式清理（`ls -a` 输出目录确认无 `.lock` 残留）。
7. 读回校验通过：非空、结构完整、序号连续；旧格式文件已迁移为新格式且原有条目无丢失。
