# Optimization Proposal 原子 Skill

## 概述

将分析结果转化为具体、可执行且可比较的优化提案，覆盖代码质量、冗余、运行性能和构建配置；本阶段只提出方案，不修改文件。

## 核心能力

- 为每个问题提供保守、平衡或激进的可选策略（按实际需要提供）
- 给出文件路径、修改说明、必要的 diff 方向、风险和影响范围
- 设计代码分割、懒加载、缓存、渲染、依赖和资源优化策略
- 关联预期收益与可验证指标，区分推测和实测

## 输入

共享上下文中的 `patterns`、`benchmarks`、`metrics_baseline`、`quality_report` 和 `redundancy_report`。

## 输出

共享上下文键：`proposals`。报告必须包含问题、候选方案、推荐方案及理由、风险、实施步骤、预期收益、验证方式和需要用户确认的事项。明确要求用户确认后再进入应用阶段。

## 执行逻辑

1. 按风险和收益排序问题。
2. 为每个问题设计可行方案并检查业务兼容性。
3. 标注可能的破坏性变更、依赖变更和性能实测要求。
4. 汇总推荐方案，等待用户确认，不自动写入代码。

## 依赖关系

- 依赖：`pattern-and-benchmark-recognition`
- 被依赖：`code-optimization`

## 完成标准

每个重要问题都有可执行方案、影响范围、风险和验证方法；推荐方案有明确理由；方案不包含未经确认的代码写入或虚构指标。

## 错误处理

模式为空时报告无法生成的原因；基准缺失时只提出代码质量方案并标注性能未评估；无法判断业务约束时列出问题等待用户确认。

## 安全边界

只生成分析和方案，不修改文件、不安装依赖、不执行构建或发布操作。
