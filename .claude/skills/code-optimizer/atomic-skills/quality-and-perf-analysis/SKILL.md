# Quality and Perf Analysis 原子 Skill

## 概述

作为感知阶段，对用户指定范围建立可复现的代码质量和性能基线，不修改源代码。

## 核心能力

- 分析圈复杂度、认知复杂度、函数/文件规模和可维护性
- 识别代码异味、潜在安全问题和高风险实现
- 收集 Lighthouse、Web Vitals、渲染/执行、资源加载和 Bundle 数据
- 区分实测、静态推断和无法执行的项目，并记录命令和环境

## 输入

- `target`：文件、目录或页面路径
- 可选的分析规则、测试命令、构建命令和性能场景

## 输出

写入共享上下文：`quality_report`、`perf_baseline`、`bundle_analysis`。报告必须包含文件路径/页面、工具和命令、指标、证据、警告及未完成项；输出路径使用主 Skill 声明的默认目录或项目既有目录。

## 执行逻辑

1. 校验目标范围和项目配置。
2. 质量静态分析与性能数据收集可并行执行。
3. 汇总结果并标注数据来源和时间。
4. 将结构化报告写入共享上下文，供模式识别使用。

## 依赖关系

- 依赖：无
- 并行：与 `redundancy-check` 并行
- 被依赖：`pattern-and-benchmark-recognition`

## 完成标准

质量报告包含复杂度、重复率、异味和安全检查；性能报告包含可获得的 Lighthouse/Web Vitals、资源或 Bundle 指标；每项数据都有真实来源或明确的未实测说明。

## 错误处理

目标不存在则报告并停止本阶段；性能服务器或工具不可用时降级为静态分析并记录；单个文件解析失败时跳过该文件并报告路径，不隐瞒覆盖范围。

## 安全边界

只读目标文件，不写源代码，不上传代码，不把密钥或环境变量写入报告。
