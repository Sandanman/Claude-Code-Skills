# Deployment Verification

## 输入

- `deployment_context`：平台、环境、版本、URL 或本地目标。
- `health_checks`：用户确认的 URL、端点、正常状态码、超时和重试次数。
- `smoke_tests`：用户指定的页面/API 和必要的认证边界。
- `logs`：可读取的部署或启动日志。
- `rollback_context`：平台支持的版本、镜像、命令或操作手册。
- `output_path`：验证报告路径。

## 执行逻辑

1. 检查验证目标和凭据边界；缺少真实 URL 时只生成检查清单。
2. 按配置执行健康检查、页面/API 冒烟测试和可选日志检查。
3. 记录状态码、响应时间、错误摘要和证据，不输出 Token 或敏感响应。
4. 仅在平台支持且上下文明确时生成回滚建议。
5. 汇总为 Markdown 或 JSON 报告，写入前确认路径。

## 结果规则

- `PASS`：已执行的必需检查均符合配置。
- `WARNING`：检查部分完成、工具不可用或存在非阻断问题。
- `FAIL`：必需检查失败或部署不可达。
- 未执行的检查标记 `SKIPPED`，不得当作通过。

## 完成标准

1. 报告列出实际执行和跳过的检查、目标、结果及证据。
2. 健康状态码和超时来自配置，不固定使用 `/health` 或 200。
3. 性能指标仅在有对应工具和目标时记录，不强制采集 FCP/LCP。
4. 回滚建议可追溯到平台和版本上下文；没有上下文则明确说明无法提供。
5. 报告存在、非空、格式可读取。

## 完成后校验

重新读取报告，检查状态汇总、时间戳、敏感信息脱敏和输出路径。缺少真实部署上下文返回 `partial`；实际检查失败返回 `failed`，不把配置生成结果当作验证结果。
