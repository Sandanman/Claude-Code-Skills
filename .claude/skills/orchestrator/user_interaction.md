# 用户交互决策点

Orchestrator 默认直接执行明确、低风险、单 Skill 请求；只有歧义、高风险、状态冲突或执行升级时才进行交互。确认一次后，下游原子 Skill 不重复询问同一事项。

## 决策点汇总

| 决策点 | 触发条件 | 默认行为 |
|---|---|---|
| D1 | 发现多个活动任务或旧任务状态冲突 | 不覆盖，要求选择任务或明确开始新任务 |
| D2 | 多主 Skill 分数接近或意图不明确 | 展示候选并请求选择/澄清 |
| D3 | 发现高风险或不可逆操作 | 展示影响范围和命令，等待确认 |
| D4 | Fast Path 需要依赖、重试、共享状态或暂停恢复 | 升级到 Durable Path，保留已有上下文 |
| D5 | Durable 校验失败或高风险任务需要反思 | 默认输出失败项；只有用户授权才反思 |

## 主 Skill 选择输出

主 Skill 确定后无需额外询问用户，但必须输出可观测性信息：

```text
主 Skill：{main_skill}
匹配关键词：{matched_keywords}
匹配分数：{match_score}
选择理由：{selection_reason}
声明依赖：{dependencies}
执行路径：{route_mode}
```

只有多候选需要用户选择时，`selection_reason` 才需要记录用户选择依据。Fast → Durable 升级时沿用原主 Skill 选择信息，追加升级原因和新的持久化/校验信息，不重复匹配或重复询问。


触发条件：`tasks/current/` 中存在多个活动任务，或旧格式任务与新格式任务同时存在。

处理规则：

- 不删除、不覆盖、不自动忽略已有任务。
- 展示任务 ID、状态、主 Skill 和完成进度。
- 用户指定任务 ID后恢复；用户明确开始新任务后创建新的唯一任务 ID。
- 只有发现单个明确关联的 Durable 任务时，才允许直接恢复。

## D2 - 多 Skill 匹配

触发条件：多个候选达到最低分且分数差距不足以自动选择，或用户请求包含多个动作。

处理规则：

- 仅展示必要候选，不读取无关 Skill 的完整正文。
- 明确单意图且唯一高置信度匹配时直接选择最高匹配 Skill。
- 用户确认后缓存选择结果，下游不重复询问。

## D3 - 高风险确认

以下操作必须在执行前确认：

- 删除、覆盖、批量移动文件。
- 修改权限、凭证、环境变量、部署或 CI 配置。
- Git commit、push、reset、分支删除或强制操作。
- 数据迁移、外部系统写入或其他不可逆副作用。

确认提示至少包含：

```text
【操作确认】
执行路径：durable
影响范围：{文件、分支或外部系统}
计划操作：{命令或变更摘要}
风险说明：{可能的副作用}
是否继续？[y/N]
```

## D4 - Fast Path 升级

触发条件：执行过程中发现依赖、第二个 Skill、确认节点、重试需求、跨步骤共享上下文、高影响失败或任务范围扩大。

处理规则：

1. 停止继续使用 Fast Path。
2. 保存已有意图、匹配结果、已完成输出和升级原因。
3. 创建 Durable 状态并继续执行。
4. 不重复执行已完成且可验证的步骤。
5. 升级后不得降级回 Fast Path。

## D5 - 校验失败与反思

Durable Path 校验失败时默认输出：

- 未通过的完成标准。
- 风险备注。
- 是否需要恢复。
- 推荐下一步。

只有以下情况触发反思：

- 用户明确要求。
- 任务风险为 high。
- L1 校验失败且反思可能改善结果。

反思默认 0 次，触发后最多 3 次；突破上限必须再次获得用户明确授权。
