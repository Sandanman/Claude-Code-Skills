# Execution Controller 原子 Skill

## 1. 核心定位

根据任务路径、依赖和计划层执行原子 Skill，持续更新 Durable 状态并保存可恢复结果。Fast Path 不创建持久化状态；一旦需要状态管理则升级为 Durable Path。

## 2. 执行规则

1. Fast Path 默认直接执行唯一低风险目标，不重试、不归档。
2. Durable Path 每个 Skill 开始前将状态更新为“执行中”，记录开始事件。
3. 按依赖顺序执行，不重复执行已完成的 Skill。
4. 成功后更新为“已完成”，写入执行摘要和核心结果。
5. 核心输出追加到共享上下文：

```markdown
<!-- atomic-skill: skill-name -->
核心输出
<!-- /atomic-skill: skill-name -->
```

6. 失败时记录错误和影响等级，更新为“失败”。
7. Durable Path 的可重试错误按有限次数重试；低影响错误允许独立分支继续；高影响错误暂停并保留恢复状态。
8. 任何确认、依赖、重试、跨步骤上下文或高影响失败都触发 `fast → durable` 升级，不允许降级。

## 3. 执行模式

`parallel_layers` 只表示计划层。默认使用 `execution_mode: serial_by_default`，不将同层计划描述为已实际并行。

只有运行环境具备状态隔离、副作用协调和失败合并能力时，才允许显式启用真实并行。

## 4. 恢复规则

发现新的任务 ID 状态文件时，读取路由模式、风险级别、依赖、执行结果、错误日志、校验级别和共享上下文。

仍兼容读取旧的 `tasks/current/task_skill.md`，但不得用新任务覆盖旧任务。已完成 Skill 不重复执行；`待恢复` Skill 先验证已有输出和外部副作用，再决定是否重试。

恢复时不得覆盖已有执行日志、错误日志和共享上下文。发现多个活动任务时要求精确选择，不自动删除或忽略旧任务。

## 5. 完成标准

- Fast Path 不产生无必要的状态写入和归档副作用。
- Durable Path 的状态转换、执行日志、错误日志和共享上下文完整。
- 依赖及计划层顺序正确，实际执行模式记录准确。
- 失败、重试、升级和暂停信息可追溯。
- 任务文件支持中断后恢复，且不重复执行已完成步骤。
